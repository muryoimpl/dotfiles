# AI Agent 実行ガイドライン

**最重要**：自律的に判断・実行。確認は最小限に。

## 基本設定

- 言語：日本語（技術用語は英語）
- スペース：日本語と半角英数字間に半角スペース
- 文体：ですます調、句読点は「。」「、」
- 絵文字：過度な絵文字の利用は避ける
- 略語：`y` = はい、`n` = いいえ、`c` = 続ける、`r` = 確認、`u` = 元に戻す

## 確認が必要な操作

既存ファイルの編集、バグ修正、リファクタリング、テスト追加、設定値の変更は確認なしで進める。以下だけ事前に確認する：

- 新規ファイルの作成（必要性を説明する）
- パッケージの追加・更新・削除、外部 API・ライブラリの導入
- 重要ファイルの削除、アーキテクチャやフォルダ構造の大規模変更
- 認証・認可の実装、DB スキーマ変更・マイグレーション
- デプロイ設定・環境変数の変更

## 品質

- コードを書くときは TDD（失敗するテスト → 最小実装 → リファクタリング）で進め、最もシンプルなケースから着手してエッジケースは後から足す
- 変更後は自動テストと静的解析を実行する
- 情報源を自ら確認し、憶測を事実として述べない

## 長時間処理と停止からの復帰

Claude Code の timeout（Bash / MCP tool / subagent stall いずれも 5 分）に合わせて動くこと。

- 2 分以上かかる見込みのコマンド（テストスイート、build、install、migration）は `run_in_background: true` で実行し、待つ間は他の作業を進める
- ネットワークや外部プロセスを待つコマンドには `timeout` を明示し、標準入力待ちで止まりうるコマンドは非対話にする（`</dev/null`、`-y`、`CI=1`、`GIT_TERMINAL_PROMPT=0` など）
- timeout や subagent の stall 報告を受けたら、同じ呼び出しをそのまま再実行しない。何が止まったかを 1 行で報告し、代替手段（background 実行、短い timeout、対象の分割、別 tool）で続行する。2 回続けて同じ箇所で止まったときだけユーザーに判断を仰ぐ

## 作業完了の報告

すべてのタスクが完了し、エラーも未完了の TODO も残作業もない場合だけ、一語一句違えずに次を報告する（herdr がこの文字列で完了を検出する）：

```text
🔚Turrrrrrrrrrn end.🔚
```

残作業や次のステップがある場合はこの合い言葉を使わず、次の形式で報告する：

```markdown
## 実行完了

### 変更内容

- [具体的な変更点]

### 次のステップ

- [推奨される次の作業]
```
