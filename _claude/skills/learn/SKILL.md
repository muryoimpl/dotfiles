# learn

このセッションの会話全体を振り返り、次のセッション以降に役立つ学びだけを LEARNING.md に残す。
LEARNING.md はセッション開始時に SessionStart hook が全文をコンテキストへ注入するので、
**短く、重複なく、事実だけ** を書く。

## 手順

### 1. 対象ファイルを決める

次の順で決め、以降 `$LEARNING` として扱う。

1. 引数 `$ARGUMENTS` があればそのパス
2. SessionStart で注入された `[LEARNING.md 読み込み済み] <path>` の path
3. どちらも無ければ `~/.claude/scripts/learning.sh path` の出力（main worktree のルート）

### 2. 既存の内容を読む

- `$LEARNING` を読む。無ければ末尾のテンプレートで新規作成する
- プロジェクトの CLAUDE.md（ルートと `.claude/CLAUDE.md`）も読む。そこに既に書いてあることは学びにしない

### 3. 学びの候補を洗い出す

セッションの最初から最後までを振り返り、4 つのセクションに分けて候補を挙げる。

| セクション | 入るもの |
|---|---|
| 失敗と対策 | うまくいかなかった手順・誤った前提と、次回どうすれば避けられるか |
| 業務知識 | ドメイン用語、業務ルール、外部システムの仕様など、コードからは読み取れない知識 |
| プロジェクト固有の作法 | ブランチ運用、レビュー慣習、テストの回し方、命名や配置の暗黙ルール |
| その他 | 上記に入らないが、次回も役立つと確信できるもの |

採用する基準（すべて満たすもの）:

- 次のセッションで同じ失敗・同じ調査を避けられる
- コード、git 履歴、CLAUDE.md、rules を読んでも分からない
- このプロジェクトで再び役立つ（今回のタスク限定の事実ではない）

除外するもの:

- 今回のタスク固有の進捗や結論
- 一般的なプログラミング知識・言語仕様
- コードを読めば分かるディレクトリ構成や関数の説明
- 秘匿情報（トークン、パスワード、個人情報）
- 確認していない推測

### 4. 既存項目と照合する

- 既存項目と同義なら追記しない
- 既存項目をより正確・具体的にできるなら、その項目を書き換えて日付を今日に更新する
- 既存項目と矛盾するなら、現状を確認したうえで新しい内容に書き換える

### 5. 書き込む

- 1 項目 1 行（長くても 2 行）。`- YYYY-MM-DD: <事実> → <どうするか>` の形
- セクション見出しは固定。空のセクションも残す
- `<!-- last-reviewed: ... -->` の行は触らない（週次レビューが更新する）
- 日本語と半角英数字の間に半角スペース

### 6. 報告する

- 学びが無ければファイルに触らず「LEARNING.md: 追加なし」と 1 行で報告する
- あれば「LEARNING.md: 追加 n 件、更新 m 件」に続けて、追加・更新した項目を 1 行ずつ列挙する
- headless（hook からの自動実行）でも同じ形式で報告する。報告は log に残る

## テンプレート

```markdown
# LEARNING.md

<!-- last-reviewed: 未実施 -->

Claude Code が各セッション終了時に更新し、セッション開始時に読み込む学びの記録。手動編集可。

## 失敗と対策

## 業務知識

## プロジェクト固有の作法

## その他
```
